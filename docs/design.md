# ハッシュでの管理

> ファイルの BLAKE3 ハッシュ、フォルダの Merkle ハッシュ、変更の検知と再ハッシュ、ドライブごとのスナップショット、重複の一覧、LAN の他の PC の閲覧は実装済みです（`crates/lisa-core/src/{db,hash,dups}.rs`、`src/scan/worker.rs`、`src/lan.rs`）。ハッシュ待ちの列を DB に残す仕組み（`hash_queue`）などは計画中です。

Lisa の目的は、複数の PC やドライブにあるファイルを、中身のハッシュで見分けて整理することです。
同じファイルがどこにあるか、どのフォルダが同じ中身か、どれが消えたり変わったりしたかを、
名前や場所によらずに分かるようにします。
保存するデータの細かい形は [schema.md](schema.md) にあります。

## 画面の階層

```
Root
├─ 端末（PC）
│   └─ ドライブ（ボリューム）
│       └─ フォルダ … ファイル
└─ …
```

- ドライブはボリューム ID で見分けます（つなぎ直しても、別の PC につないでも同じドライブと分かる）。
- LAN にいる他の PC の Lisa も、`Root` の下に別の「端末」として並び、相手の DB からドライブとフォルダを取って同じ木の中で見られます（`lan.rs`）。

## ファイルのハッシュ

- 中身の BLAKE3 ハッシュを使います。

## フォルダのハッシュ

- 子の一覧から作る Merkle ハッシュです（`crates/lisa-core/src/hash.rs` の `folder_hash` / `tree_bytes`）。
- 子を名前順（`name::hash_order`）に並べ、子ごとに `種類（1 バイト: f/d/l/o） + NFC の名前のバイト長（u64 LE） + NFC の名前 + （ハッシュがあれば 1 + ハッシュ 32 バイト、無ければ 0 + 大きさ u64 LE）` をつないで BLAKE3 でハッシュします（名前は長さを前に付けて書くので、区切りの取り違えが起きません）。
- OS が作るゴミファイル（`.DS_Store`、`Thumbs.db` など）は含めません。
- 中身が同じフォルダは、場所や名前が違っても同じハッシュになります。画像キャッシュのキーも、
  今のノード番号からこのハッシュに置き換えます。

## 変更の見つけ方

- 大きさと更新日時は「変わったかもしれない」の手がかりにだけ使い、変わったかどうかは
  ハッシュで決めます。
- ハッシュを計算する順番待ちの列を持ち、アプリを終わっても残します。失敗したものは、間隔を
  指数的に空けて（exponential backoff）やり直します。
- 今画面で見ているものは、列の先に回して優先して計算します（on-demand priority）。

## スナップショット

- ある時点の木を、Root のハッシュで表すスナップショットとして残します。
- スナップショットは、前の Root のハッシュを指して鎖のようにつなぎます。いつ何が変わったかを
  たどれるようにするためです。
