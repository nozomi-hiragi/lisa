# 入力の扱い

トラックパッドとマウスの操作は `src/input/` にあります。

## マウスとトラックパッドの見分け

- スクロールの単位で見分けます。行単位がマウスのホイール、ピクセル単位がトラックパッドです。
- Magic Mouse はピクセル単位で来るので、トラックパッドと同じ扱いになります。
- winit / Bevy のピクセル単位の動きは物理ピクセル（Retina では 2 倍）なので、論理ピクセルに
  直して使います。macOS の NSEvent から読む値は、もともと論理ピクセルです。

## macOS の NSEvent モニタ

winit は「指の段階」と「慣性の段階」を 1 つにまとめてしまうため、指がパッドに触れたのか、
慣性が続いているのかを区別できません。macOS では、ウィンドウに届くスクロールの NSEvent を
ローカルモニタで覗き（`mac_scroll.rs`）、次の値をそのまま使います。イベントは変えずに
返すので、winit にもそのまま届きます。

- `phase`: 指の段階（MayBegin = 触れた、Began、Changed、Ended、Cancelled）
- `momentumPhase`: 慣性の段階（Began、Changed、Ended）
- `scrollingDeltaX/Y`: 動き（論理ピクセル）

macOS 以外や、モニタが付かなかったときは、winit の段階から推し量ります（下の「推し量り」）。

## スクロールの状態機械

`scroll_input.rs` の `ScrollMachine` が、2 本指スクロールの状態を持ちます。時刻を引数で
受け取るので、ウィンドウ無しでテストできます。

```
             触れた / 始まり                     離した
   Idle ───────────────────────> Touching ─────────────────> AfterLift
    ^                              ^   ^                        │
    │            触れた（MayBegin） │   │ 慣性が速いまま終わった  │ 慣性が始まった
    │   ┌──────────────────────────┘   │ （つかんだと推し量る）   v
    │   │                              └──────────────────── Momentum
    │   │                                                       │
    └───┴──── 慣性が終わった / 0.1 秒途切れた ─────────────────────┘
              （AfterLift は 0.08 秒何も来なければ Idle へ）
```

出す動作:

- `TouchBegin` — 指がパッドに触れた（動いていなくても）。動いているもの（ばね、ズーム、
  隣への移動、フェード）は、その場で止めて指でつかんだ状態にする。
- `Touch` — 指の動き。
- `Lift` — 指を離した。この瞬間から、離したときの速さで重力の動きに入る。
- `Momentum` — 慣性（今は使わずに捨てる。離したあとの動きは重力で作る）。

決まり:

- 慣性は、それを生んだスワイプのものです。使わないと決めたら（`drop_momentum`）、その慣性が
  終わるまで、来た入力はすべて捨てます。今は慣性を使わないので、来たらすぐ捨てます。
- 慣性の入力は、決して新しい指にはなりません。
- 指の合図（MayBegin）が来なくても、速く流れていた慣性が急に終わったら、指が触れて止めたと
  みなします。そのあと 0.2 秒何も来なければ、軽く触れて離した（タップ）ことにします。

推し量り（macOS 以外）:

- 指を離して 0.08 秒以内に来た入力は慣性とみなします。
- 慣性の途中に動きの無い「始まり」が来たら、新しい指とみなします。

## カメラの動き

- 2 本指（と中ボタン）では、カメラが指について動きます。ピンチとホイールは、カーソルの位置を
  中心に拡大縮小します。
- **ラバーバンド**: 指が乗っている間、行き先の無い方向へはみ出すと、はみ出すほど重くなります
  （画面の大きさの 35 % に近づいていく）。
- **隣**: フォルダやファイルを開いているとき、周りには親のタイルの隣（フォルダかファイル）が
  見えています。隣がある範囲（親のどのタイルを画面に収めても、その枠の真ん中が来る範囲）の中は、
  縦も横も斜めも重さなしで動けます。
- **スクロール**: フォルダの中はスクロールしません（中身は全部タイルにして収める）。

## 離したあと

指を離したら、離す直前の速さ（移動と拡大縮小）をそのまま持って動き続け、行き先へ寄って止まります
（`settle.rs` の `coast_step`）。移動もズームも同じ流れです。

- **勢い**: 指数関数的に弱めます（時定数 `MOMENTUM_SECONDS`）。終わり際ほどよく効く摩擦です。
- **寄せ方**: 行き先とのずれが指数関数的に縮むように寄せます（時定数 `PULL_SECONDS`）。勢いも
  ずれも十分小さく（ずれ 0.3 px 未満）なったら、その場で止まります。最後に跳ぶことはありません。
- **つかむ**: 動いている途中で指を置くと（ピンチ、中ボタンも）、その場でつかみます。
- macOS の慣性のスクロールは使わずに捨てます（離したあとの動きは、ここで作る）。

### ピンチ（ホイール）の行き先

止まれる段を倍率の小さい順に並べます（`zoom_levels.rs` の `zoom_ladder`）。

- カーソルの下（タイルの隙間なら、いちばん近い）の子を画面に収める大きさ
- 今のフォルダの中を拡大して見る段（`grid_levels`）。ウィンドウの短い辺の向き（横長のウィンドウ
  なら縦）にタイルが見切れずにちょうど k 個収まる倍率を、k = 2 から「全体で並ぶ個数 − 1」まで。
  中身が多いフォルダほど段が細かくなります
- 今のものを画面に収める大きさ
- 親の中を拡大して見る段と、親を画面に収める大きさ

行き先は、ピンチで動かした先（始めた倍率＋ピンチの幅＋離したときの勢いを 0.1 秒ぶん）に
いちばん近い段です。ただし、その向きに十分動かしていれば、少なくとも 1 段は進みます。「十分」は
`ZOOM_COMMIT_LN`（0.18、約 1.2 倍）と、次の段までの半分の小さいほうです。段が細かければ少しの
ピンチで 1 段進み、段が粗ければ（中身の少ないフォルダから子へなど）約 1.2 倍のピンチで進みます
（`choose_zoom`）。子のプレビューが小さくても、大きくズームする必要はありません。段は、ピンチを
始めたときに開いていたものを基準に決めます。

決まった段の倍率へ寄せ、位置はその真ん中（中を拡大して見る段なら、タイルの切れ目に合わせた所）へ
寄せます。

### 2 本指（中ボタン）の行き先

倍率は変えず、位置だけを寄せます（`choose_pan`）。

- 離したときの勢いを `PAN_LOOKAHEAD`（0.25 秒）先まで見込んだ所にいちばん近い、同じ階層の
  タイルへ。
- 見込んだ先が今のままでも、`FLICK_PX_PER_SECOND`（毎秒 400 px）より速く動かしていれば、その向きの
  隣へ 1 つ進みます。斜めなら、向きにいちばん沿った隣を選びます。
- フォルダの中を拡大して見ているとき（収める大きさより小さい倍率）は、見込んだ先で、画面の端が
  タイルの切れ目に来る所へ寄せます（`grid_snap`）。左右と上下それぞれ、どちらかの端をそろえる
  位置のうち、画面の真ん中にいちばん近いタイルが見切れず、今の位置にいちばん近い所を選びます。
- Root より縮めていたら、Root の大きさへ寄せます。

### 開いている場所の切り替え

開いている場所は、止まるのを待たずに切り替わります（`refocus`）。動かしている最中も、ピンチの最中も、
離したあとも、毎フレーム、行き先の候補（今のもの、中の子、親、親の中の隣。中を拡大して見る段は
そのフォルダの候補）のうち、今の位置と倍率にいちばん近いものを探します。近さは「倍率の比の対数」と
「位置のずれ（その候補を収めたときの画面の幅で割ったもの）」の和です。それが今開いているものより
`REFOCUS_MARGIN`（0.05）以上近ければ、開いている場所（パンくず、隣、動ける範囲）と場面をその場で
切り替えます。カメラは動かしません。余裕を持たせているのは、境目で行ったり来たりしないためです。

止まったら、ピンチや 2 本指で決めた行き先を開きます（途中で切り替わっていれば何もしない）。

### 離したとみなすとき

- 2 本指: macOS では「離した」の段階が来たとき。
- ピンチ: macOS では、ピンチの NSEvent（Magnify）の段階も覗いて、指が乗っているかを見ます
  （`mac_scroll.rs`）。指を離した瞬間に動き出します。ほかでは入力が 0.04 秒途切れたとき。
- ホイール: 0.15 秒止まったとき。ホイールは速さを持ち越しません。
- 中ボタン: ボタンを離したとき。

## クリック

- クリック、右クリック、Esc で移るときは、決まった時間（0.4 秒）のズームです。
- クリックは、画面に見えている図のとおりに選びます（`view.rs` の `hit_path`）。今開いているものへの
  道のりを Root からたどり、クリックした所でそこから外れた最初のものへ移ります。今のものの中なら
  その子、外なら隣や親の隣、何も無い所ならそこを含むもの（外へ戻る）です。

## 調整できる値

設定のポップアップで変えられるもの（README の「設定」）のほかに、`src/input/` の各ファイルの先頭に
定数としてまとめています。

| 定数 | ファイル | 値 | 意味 |
| --- | --- | --- | --- |
| `MOMENTUM_SECONDS` | settle.rs | 0.12 秒 | 離したあとの勢いが弱まる時定数。小さいほど摩擦が強い |
| `PULL_SECONDS` | settle.rs | 0.12 秒 | 行き先へ寄っていく時定数。小さいほど強く吸い付く |
| `PAN_LOOKAHEAD` | settle.rs | 0.25 秒 | 2 本指で離したとき、勢いを見込む時間 |
| `FLICK_PX_PER_SECOND` | settle.rs | 400 | これより速く離したら、少なくとも隣へ 1 つ進む |
| `REFOCUS_MARGIN` | settle.rs | 0.05 | 開いている場所を切り替えるのに要る、近さの差 |
| `ZOOM_COMMIT_LN` | zoom_levels.rs | 0.18 | ピンチでこれだけ（倍率の比の対数）動かすと、次の段へ進む |
| `ZOOM_LOOKAHEAD` | gesture.rs | 0.1 秒 | ピンチを離したとき、勢いを見込む時間 |
| `RUBBER_LIMIT` | gesture.rs | 0.35 | ラバーバンドの限界（画面の大きさに対して） |
| `WHEEL_ZOOM_STEP` | gesture.rs | 0.12 | マウスのホイール 1 段の拡大縮小 |
| `TRACKPAD_SCROLL_ZOOMS` | gesture.rs | false | true にすると、2 本指の縦スクロールで拡大縮小する |
| `MOMENTUM_GAP` | scroll_input.rs | 0.08 秒 | 離してからこれ以内の入力は慣性（推し量りのとき） |
| `EARLY_END_PX` | scroll_input.rs | 3.0 | 慣性がこれより速いまま終わったら、つかんだとみなす |

## 調べるとき

`LISA_INPUT_LOG=1 cargo run`（デバッグビルド）で、`/tmp/lisa-input.log` に生の入力と状態の
移り変わりを書き足します。おかしな動きを再現したら、このログの並びをそのまま
`scroll_input.rs` のテストに起こせます。
